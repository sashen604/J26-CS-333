# Drift detection results: CUSUM vs EWMA (Pillar 4)

Features: HF mirror reconstruction, not official CICIoT2023 — see data/README.md.

Generated by `python p4_robustness/experiments/drift_experiment.py`. Do not edit by hand.

**Data:** CICIoT2023 subset (HF mirror), Mirai vs benign. 7 window-size leakage features are excluded and 28 features are quantised to 0.1. See `data/README.md` for provenance, the window-size leakage section and limitations. **Model:** XGBoost proxy, which is not P3's fusion model.

**Caveat:** benign and Mirai are almost perfectly separable on this subset, so the attack-side shift in the monitored scalar is very large. Fast detection here reflects that, not the detectors' sensitivity to subtle drift.

**Caveat:** all 520 streams (500 for calibration, 20 per scenario) resample the same test rows, so the ± values likely understate the true uncertainty.

## Setup

- Monitored scalar: `logit_fused_windowed_anomaly_score`, the logit of the mean P(attack) over 50-row windows, with p clipped to [1e-06, 1 - 1e-06].
- Reference: 399 benign-only validation windows. mu0 = -7.7321, sigma = 0.8681 (measured 0.8681). Sigma floor 0.001 used: **no**.
- For comparison, the raw windowed P(attack) on the same windows: mean = 7.227e-04, sigma = 1.310e-03.
- Streams come from the test split, sampled without replacement with a fixed seed per run. 200 benign windows, then 100 drift windows. Drift starts at window 200.
  - Scenario A (abrupt): every drift window is 100% Mirai.
  - Scenario B (gradual): Mirai share rises linearly from 0% to 30% (rounded to whole rows).
- CUSUM k = 0.5 sigma. EWMA lambda = 0.2. Both restart automatically after an alarm.
- Seeds 0–19 for the scenarios. Values below are mean ± std over 20 seeds (sample std).

## Calibration (target: 1 false alarm per 1000 windows)

Benign-only test streams: 500 streams × 300 windows = 150,000 windows (seeds 1000–1499). One 300-window stream cannot measure a rate of 1/1000, so many streams were pooled. All streams draw from the same 19,999 benign test rows, so they are not independent.

## Scenario C: covariate drift in benign traffic

Benign test rows only (no Mirai rows). Windows 0–199 are unmodified. In windows 200–299, 5 features are multiplied by a factor rising linearly from 1.0 to 2.0 (multiplicative only). Scaled features in `QUANTISED_FEATURES` are re-rounded to 0.1. The calibrated h and L from above are reused, not recalibrated.

Features scaled: the top 5 by gain that are continuous and scale-safe. Excluded: protocol codes, flag or 0–1 share features, window-dependent features (the excluded set plus `Std` and `Variance`), and `Time_To_Live` (hard upper bound of 255).

Out of range means outside the [min, max] of that feature over the full test split (both classes).

**Validity caveat (Header_Length):** its test-split maximum is exactly 60, possibly the TCP header byte limit. Scaling took 6,023 of 99,000 scaled rows (6.1%) above 60, which may be physically invalid. This is unresolved until the features are recomputed from the PCAPs.
