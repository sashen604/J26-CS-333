# Drift detection results: CUSUM vs EWMA (Pillar 4)

Generated by `python p4_robustness/experiments/drift_experiment.py`. Do not edit by hand.

**Data:** CICIoT2023 subset (HF mirror), Mirai vs benign, `Number` excluded. See `data/README.md` for provenance and limitations. **Model:** XGBoost proxy, which is not P3's fusion model.

**Caveat:** benign and Mirai are almost perfectly separable on this subset, so the attack-side shift in the monitored scalar is very large. Fast detection here reflects that, not the detectors' sensitivity to subtle drift.

**Caveat:** all 520 streams (500 for calibration, 20 per scenario) resample the same test rows, so the ± values likely understate the true uncertainty.

## Setup

- Monitored scalar: `logit_fused_windowed_anomaly_score`, the logit of the mean P(attack) over 50-row windows, with p clipped to [1e-06, 1 - 1e-06].
- Reference: 399 benign-only validation windows. mu0 = -11.2308, sigma = 0.7867 (measured 0.7867). Sigma floor 0.001 used: **no**.
- For comparison, the raw windowed P(attack) on the same windows: mean = 2.134e-05, sigma = 3.915e-05.
- Streams come from the test split, sampled without replacement with a fixed seed per run. 200 benign windows, then 100 drift windows. Drift starts at window 200.
  - Scenario A (abrupt): every drift window is 100% Mirai.
  - Scenario B (gradual): Mirai share rises linearly from 0% to 30% (rounded to whole rows).
- CUSUM k = 0.5 sigma. EWMA lambda = 0.2. Both restart automatically after an alarm.
- Seeds 0–19 for the scenarios. Values below are mean ± std over 20 seeds (sample std).

## Calibration (target: 1 false alarm per 1000 windows)

Benign-only test streams: 500 streams × 300 windows = 150,000 windows (seeds 1000–1499). One 300-window stream cannot measure a rate of 1/1000, so many streams were pooled. All streams draw from the same 19,999 benign test rows, so they are not independent.

Detection delay is the window index of the first alarm at or after window 200, minus 200, so 0 means an alarm in the first drift window. It is averaged over seeds that detected the drift.

**Scenario B note:** after rounding to whole rows, the first 4 ramp windows contain 0 Mirai rows. Window 204 is the first to contain any (1 of 50). A delay of 4 therefore means an alarm at the first window containing any Mirai traffic. On this subset, one Mirai row in a window is enough to push the logit far above the reference.
